# Codex 浏览器操作经验

本文件记录 2026-09-29 的一次真实课堂经验。只将页面结构作为定位线索；工具 API、页面控件和路由可能变化。先读当前工具文档、观察页面，再执行。示例不包含真实课程或个人标识。

## 工具与标签页

- 本次使用 `cua_repl` 控制已登录的 Chrome。其他 agent 需要提供等价的 DOM/辅助功能树、截图、点击和输入能力；光安装 skill 不会获得浏览器访问能力。
- 第一次调用遵守工具入口要求，例如单独执行 `await cua.getState()`，随后读取其返回的说明。不要把初始化、点击和等待混在要求单次初始化的调用中。
- 用户指定 Chrome 时使用 Chrome，不能把宿主内嵌浏览器的当前页当成用户选定的浏览器。
- 根据实际发现的浏览器/标签 ID 建立句柄。句柄可跨调用复用；上下文压缩后按工具要求恢复文档，不因新消息重建全部会话。
- 点击正在上课入口可能新开标签。检查标签列表并核对课程标题，再绑定该新标签。
- 本次页面路径包含 `/lesson/fullscreen/v3/`。`ppt` 和 `subjective` 表示不同内容视图；路径末尾数字与课件显示页码不一定一致，不要根据页码拼接 URL。

## 小批量只读检测

推荐让检测仅返回新题候选，再交回 agent 阅读、解题和操作。不要把答案选择、提交或自动调用外部模型塞进轮询代码。

伪代码（需使用当前工具实际支持的 API）：

```text
在本次课堂未结束且用户未叫停时：
    读取当前可见页面
    如果浏览器断开或登录失效：报告并停止
    如果本次课堂明确结束：停止
    如果有当前未完成题目、作答入口或投票表单：
        立即返回当前页面状态，交给 agent 处理
    否则等待约 10 秒，继续检查
    每批最多约 40–50 秒，交回会话处理新消息
```

本次可用的工具方法包括 `tab.getAXState()` 和 `tab.playwright.domSnapshot()`。短等待曾使用 `clock.sleep`，后改为在 `cua_repl` 内用有界循环调用文档支持的 `tab.playwright.waitForTimeout(10000)`。这是当前会话内的轮询，不是后台服务；如果宿主不允许这种等待，使用其支持的可中断等待机制。

- 实际检测使用过“倒计时”“剩余 … s”“未完成”“提交答案”“作答”等可见词。它们只是提示，不是完整协议，投票和无时限题还应结合当前表单状态识别。
- 页面快照可能包含整段课堂动态历史和用户脚本的隐藏设置。不要把其中“自动作答”的菜单文字当作正在出题，也不要只要见到历史“已完成”就跳过新题。
- 本次页面的“几分钟前”文本不一定随时间刷新，不能单凭它不变判断断线。
- 图片课件内容不一定在辅助功能树里；完整题干需要时用截图读取。

## 表单操作：观察后再定位

下面是本次曾有效的定位方式，必须先在当前快照中看到对应文字或结构：

```javascript
await classroom.playwright.getByText('作答', { exact: true }).click();
// 重新观察，确认原生文本框和提交按钮确实出现。
await classroom.playwright.getByRole('textbox').fill(answer);
await classroom.playwright.getByText('提交答案', { exact: true }).click();
// 重新观察，等待原生“已完成”及“我的回答”；不把“提交中...”当成功。
```

这里的 `classroom` 是根据实际页面建立的句柄，`answer` 是 agent 阅读题目后生成的简短回答。这段代码不适合不经观察直接整段粘贴运行。

### 提醒挡住“作答”

曾出现：右下角提醒浮层覆盖原生按钮，第一次点击后输入框没出现。处理方式是先检查新状态，截图确认按钮尚可点击的区域，再点击。不要反复点击相同失效位置，也不要点击提醒里的“AI 解答”代替原生输入。

### 提交异步完成

曾出现：点击后第一份快照仍是“提交中...”，下一份才有“已完成”和已提交文本。只在成功状态出现后计数；网络超时后先查看已提交状态，不能盲目再交一次。

### 答题后跟回直播页

主观题详情可能一直留在主体区域，而左侧课堂动态已经翻页。先关闭详情，再点击当前“正在放映”对应条目。不要刷新页面或根据课件页码构造路由。

本次经 DOM 观察发现详情关闭图标位于 `header.answer__header`，带有 `i.icon-guanbi2`。这个类名不是稳定接口，只能在当前 DOM 验证后使用。

### 止于实际结束

本次结束时同时出现导航事件“下课啦！”和提示“当前课程已结束。”。停止轮询并简述提交结果。单张幻灯片写“谢谢”、没有翻页，或某个课件“结束放映”都不一定代表整堂课结束。

## 已验证与未验证

- 实测：一个 Chrome 会话、一堂课、三道限时英文主观题，经页面输入后分别确认“已完成”。
- 未验证：所有学校部署、所有投票/选择题布局、重新连接后的恢复、长时间后台运行和极短时限题。
- 十秒轮询减少发现延迟，但工具调用、截图识别、推理和提交仍需时间；不保证每道题都能赶上。
- 不需要复制任何 Cookie、密钥、账号、学生姓名、学号或真实课堂地址来复用这些步骤。
